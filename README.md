# Sky (Ari AI)

Sky (Ari AI) is a conceptual architecture for an intentional AI mind.

It combines:
- Reasoning design (how the system evaluates ideas)
- Decision logic (how it chooses actions)
- Salience models (how it prioritizes attention)
- Internal regulation concepts (homeostasis and metabolic analogies)
- Core principles and morals (how it behaves under constraints)

The project is currently a structured knowledge base written in plain-text modules.

## What This Is

Sky is not a single runnable app yet. It is a blueprint for building one.

Think of it as:
- Part cognitive architecture
- Part behavior policy framework
- Part implementation design draft

## Why It Matters

Most AI projects start from tools and models first.
Sky starts from identity, cognition, priorities, and ethics first, then maps those into implementation.

This makes it useful for teams that care about:
- Consistent behavior over time
- Value-aligned decision making
- Explainable prioritization
- A coherent "personality" or operating style

## Repository Map (High-Level)

- Cognitive Reasoning Core: central reasoning model and thought-process framing.
- Oroboro Decision Engine: decision-flow logic and action selection ideas.
- Storage Hopper: memory/storage handling concepts.
- Homeostasis / Metabolic System: self-regulation and stability analogies.
- AI Salience: model-specific salience notes and synthesis documents.
- Core Principles / Morals: behavior constraints and guiding ethics.
- MIDI: signal/event interpretation concepts for interaction streams.
- Tool: tooling and operational behavior notes.

## What You Can Do With This

- Use it as a specification source for an AI agent implementation.
- Translate each text module into code modules and interfaces.
- Run consistency reviews across reasoning, morals, and salience.
- Build evaluation tests that check whether implementation matches intent.

## Suggested Build Path

1. Define a canonical module schema (inputs, outputs, constraints per file).
2. Convert decision and reasoning files into a deterministic core loop.
3. Add a salience scoring layer with explicit weighting rules.
4. Add memory/store behavior from Storage Hopper.
5. Add principle checks as a final decision gate.
6. Add observability logs for explainability and debugging.
